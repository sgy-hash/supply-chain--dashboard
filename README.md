# Supply Chain Operations Dashboard | 供应链运营工作台

基于 Python、Streamlit、Pandas 与 Plotly 的库存及物流分析项目。使用明确的业务规则识别风险，支持 Excel 上传、联动筛选与结果导出。没有接入生成式 AI，也不是需求预测模型。

## 本地运行

建议 Python 3.11 或 3.12。

```bash
python -m pip install -r requirements.txt
python -m streamlit run streamlit_app.py
```

Windows 也可双击 `run_local.bat`。启动后默认加载模拟数据。

## 功能

- 库存金额、周转天数、缺货、高库存与无销量记录分析。
- 品类、仓库、状态、关键词筛选联动总览、图表和导出。
- 物流按相关 SKU、起始仓联动，另支持承运商与发运日期筛选。
- 补货按提前期、安全库存与最小起订量计算。
- Excel 导出当前筛选范围，上传缺少物流表仍可分析库存。
- 无匹配记录、非法数字和重复 SKU×仓库快照有明确反馈。

## 数据格式

库存工作表命名为 `库存明细`，必要字段：`SKU`、`当前库存`、`近30天出库量`。
可选字段：货品名称、品类、仓库、期初库存、在途库存、安全库存、近90天补货次数、补货提前期(天)、单位成本、最长库龄(天)、最小起订量。
每个 SKU×仓库限一条库存快照；数字需非负且有限。缺少可选列会使用默认值并提示，已提供列中的无效数字会被拒绝。

物流工作表命名为 `物流明细`，必要字段：运单号、承运商、计划运输天数。
可选：SKU、发运日期、起始仓、目的地、发运数量、实际运输天数、运输成本。
实际运输天数为空表示运输中。为联动筛选提供 SKU 和起始仓；未匹配的记录不会纳入筛选结果。

## 指标与边界

- 日均出库 = 出库量 / 出库数据对应天数。默认是30天；修改天数不意味着获得了新的历史数据。
- 平均库存 = (期初库存 + 当前库存) / 2。
- 周转天数 = 平均库存 / 日均出库；无销量时不计算。
- 库存覆盖天数 = (当前库存 + 在途库存) / 日均出库。
- 订货点 = 日均出库 × 补货提前期 + 安全库存。
- 有需求且可用库存低于订货点时，补至 max(日均出库 × 目标覆盖天数, 订货点)，扣除可用库存，按 MOQ 向上取整。
- 延误：实际天数减计划天数严格大于配置阈值；准时率分母仅为已完成运单。
- 风险优先级：无销量、缺货、呆滞、高库存、正常；单条记录仅展示一个状态。
- SKU风险计数为 SKU×仓库记录数；平均周转为记录简单平均，不是财务金额加权周转。
- 库存是快照，无历史趋势。日期筛选仅用于物流。
- 未按到货日期分配在途库存，未纳入批次、保质期、损耗率、季节性或服务水平；生鲜补货应先补充这些约束。
- 金额假设统一为人民币；示例是可重新生成的模拟数据。

## 测试

```bash
python -m unittest -v test_dashboard.py
python smoke_test.py
```

测试覆盖 MOQ、短目标覆盖期、零销量、非法数值、重复快照、物流延误边界、空结果导出以及 Streamlit 页面交互。

## 部署与开源

上传项目到自己的 GitHub 公开仓库，然后在 Streamlit Community Cloud 选择仓库，入口为 `streamlit_app.py`。MIT 许可证适用于本项目代码；依赖遵循各自许可证。

上传工作簿在服务端内存及 Streamlit 缓存中处理，不会由本应用写入仓库。公共部署请仅使用适合公开演示的数据。不要提交 `.streamlit/secrets.toml`。

## 文件

`core.py` 计算逻辑；`streamlit_app.py` 界面；`test_dashboard.py` 回归测试；`generate_sample.py` 生成模拟工作簿；`.github/workflows/tests.yml` 自动测试；`.streamlit/config.toml` 主题。
